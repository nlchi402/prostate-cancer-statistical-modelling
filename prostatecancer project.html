Clinical Predictors of PSA: Statistical Modelling and Model Selection in R

Author

Chi Linh Nguyen

0.1 Project aim

This project investigates how a set of clinical measurements relate to log prostate-specific antigen (lpsa) and how different model-building choices affect predictive performance.

The analysis is deliberately focused on data analysis and statistical modelling, rather than making clinical claims. The dataset is small, observational, and historical, so results are interpreted as statistical associations within this sample rather than causal or current clinical conclusions.

The question is:

Which variables are most informative for log PSA, and how does model complexity affect performance on unseen data?

The result for gleason is a useful example of why the correlation analysis matters. It may contain useful information on its own, but it is strongly related to pgg45 and other predictors, so the model has more difficulty separating its individual contribution. These coefficients are interpreted as associations within this dataset, not causal effects.

7 Evaluate generalisation with holdout data and cross-validation

7.1 Performance on the predefined test set

mse <- function(model, newdata) {
  mean((newdata$lpsa - predict(model, newdata = newdata))^2)
}

candidate_models <- list(
  Full = full_model,

7.2 Ten-fold cross-validation on the training data

A single 30-observation test set can give a noisy ranking. Ten-fold cross-validation gives a second view by repeatedly fitting each fixed candidate formula on different subsets of the 67 training observations.

candidate_formulas <- list(
  Full = formula(full_model),
  Reduced = formula(reduced_model)
)

set.seed(123)
folds <- vfold_cv(train_data, v = 10)

fold_mse <- function(split, model_formula) {
  analysis_data <- analysis(split)
  assessment_data <- assessment(split)

  fitted_model <- lm(model_formula, data = analysis_data)
  predictions <- predict(fitted_model, newdata = assessment_data)

  mean((assessment_data$lpsa - predictions)^2)
}

cv_fold_results <- imap_dfr(
  candidate_formulas,
  function(model_formula, model_name) {
    tibble(
      model = model_name,
      fold = seq_along(folds$splits),
      MSE = map_dbl(
        folds$splits,
        ~ fold_mse(.x, model_formula)
      )
    )
  }
)

cv_summary <- cv_fold_results |>
  group_by(model) |>
  summarise(
    mean_CV_MSE = mean(MSE),
    sd_CV_MSE = sd(MSE),
    .groups = "drop"
  ) |>
  arrange(mean_CV_MSE)

cv_summary
# A tibble: 2 × 3
  model   mean_CV_MSE sd_CV_MSE
  <chr>         <dbl>     <dbl>
1 Full          0.599     0.400
2 Reduced       0.602     0.348

The full model has the lowest mean 10-fold cross-validation MSE at approximately 0.599. The full model performs only slightly better than the reduced model in cross-validation (0.599 vs 0.602). The difference is very small, so there is no clear advantage for either model. Together with the holdout result, this suggests that the extra predictors do not provide a consistent improvement in out-of-sample performance.

8 Sensitivity analysis: Numeric versus dummy-coded Gleason score

In the full regression model, gleason is treated as a numeric variable. This assumes that moving from Gleason 6 to 7 has the same effect as moving from 7 to 8 or from 8 to 9.

As a sensitivity check, gleason is also treated as a factor so that each score level can have its own coefficient. This is an exploratory check and does not change the full-versus-reduced model comparison above.

First, check the number of observations in each Gleason category.

count(train_data, gleason)
# A tibble: 4 × 2
  gleason     n
    <dbl> <int>
1       6    25
2       7    38
3       8     1
4       9     3

The training data are very uneven across Gleason categories. Because Gleason 8 and 9 have very few observations, their dummy-variable estimates are likely to be unstable.

To compare the two coding approaches, the same small set of other predictors is used in both models.

gleason_levels <- sort(unique(train_data$gleason))

train_gleason <- train_data |>
  mutate(
    gleason_factor = factor(
      gleason,
      levels = gleason_levels
    )
  )

numeric_gleason_model <- lm(
  lpsa ~ lcavol + lweight + lbph + svi + gleason,
  data = train_gleason
)

factor_gleason_model <- lm(
  lpsa ~ lcavol + lweight + lbph + svi + gleason_factor,
  data = train_gleason
)

gleason_comparison <- tibble(
  coding = c("Numeric", "Factor / dummy-coded"),
  AIC = c(
    AIC(numeric_gleason_model),
    AIC(factor_gleason_model)
  )
)

gleason_comparison
# A tibble: 2 × 2
  coding                 AIC
  <chr>                <dbl>
1 Numeric               156.
2 Factor / dummy-coded  157.

The numeric model has a lower AIC than the dummy-coded model (approximately 156 vs 157). This suggests that allowing separate coefficients for each Gleason category does not improve the training-data fit enough to justify the additional parameters.

For the dummy-coded model, Gleason 6 is the reference group. Gleason 7 has an estimated coefficient of about 0.38, meaning its estimated lpsa is higher than Gleason 6 after controlling for the other predictors. However, the p-value is about 0.098, so the difference is not statistically significant at the 5% level.

The estimates for Gleason 8 and 9 are close to zero and have very large p-values. These estimates are also highly uncertain because there is only one Gleason 8 observation and three Gleason 9 observations in the training data.

Overall, the sensitivity analysis does not provide a strong reason to prefer dummy coding. The numeric model has a lower AIC, while the higher Gleason categories are too sparse to estimate reliably. Therefore, if Gleason is included in the model, treating it as numeric appears to be the simpler choice for this dataset.

9 Final discussion and limitations

9.1 Main findings

  1. lcavol shows the clearest and most consistent association with log PSA. lcavol has a strong positive relationship with lpsa in the EDA and remains strongly significant in the full regression (estimate ≈ 0.58, p < 0.001).

  2. Some predictors contain overlapping information, but multicollinearity is not severe. The strongest correlations include gleason with pgg45 (r ≈ 0.76) and lcavol with lcp (r ≈ 0.69). The highest VIF is about 3.31, so the overlap should be considered when interpreting coefficients but does not appear extreme.

  3. The extra predictors in the full model are not clearly justified.
    The nested F-test gives p = 0.169, so there is not enough evidence that adding age, lcp, gleason, and pgg45 significantly improves the reduced model. AIC slightly favours the reduced model, while BIC gives stronger support to it.

  4. The reduced and full models perform similarly across validation methods. The reduced model performs better on the predefined test set, while the 10-fold cross-validation results are very close between the two models. This suggests that the additional predictors do not give a clear improvement in out-of-sample performance.

  5. The Gleason sensitivity analysis does not provide a strong reason to use dummy coding. The numeric model has a lower AIC, while the very small number of Gleason 8 and 9 observations makes the separate category estimates uncertain.

9.2 Limitations

  • The dataset is small, with 97 observations in total and only 67 used for model fitting.
  • Several predictors are correlated.
  • Some Gleason categories are extremely sparse.
  • The data are observational, so coefficients should be interpreted as associations rather than causal effects.
  • According to the supplied exercise context, the data come from a historical single-hospital cohort of patients who underwent radical prostatectomy. Results therefore should not be assumed to generalise directly to different hospitals, patient groups, or modern clinical practice without external validation.

9.3 Conclusion

Overall, lcavol shows the clearest and most consistent association with log PSA in this dataset. The full model fits the training data well, but the nested F-test, AIC and BIC suggest that the extra predictors do not add enough value to justify the added complexity. The validation results also show that model performance is sensitive to how the data are split. Given the small sample size, the reduced model seems to be a reasonable and simpler choice.
